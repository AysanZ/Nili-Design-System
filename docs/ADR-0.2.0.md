## ۱. رجیستری و مدل توزیع

### مسئله

`@nili/ui` یک پکیج npm است. مصرف‌کننده کامپوننت را ایمپورت می‌کند و اگر بخواهد
رفتارش را عوض کند، یا باید با `className` سر کند یا فورک بگیرد. این برای
یک تیم محصولی کافی است و برای چند تیم در یک سازمان کافی نیست — هر تیمی
یک نیاز خاص دارد که به آپ‌استریم مربوط نیست.

### تصمیم

هر دو مدل، از یک منبع.

```
scripts/build-registry.mjs
        │
        ├──→ registry/*.json ──→ npx nili add button   (کپی سورس)
        │
        └──→ registry/*.json ──→ پنل پراپ‌های استودیو  (متادیتا)
```

اسکریپت `src/components/**` را با `ts-morph` می‌خواند و برای هر پوشه یک
JSON می‌سازد: فایل‌ها، گراف وابستگی، و برای هر کامپوننت صادرشده،
واریانت‌های `cva` و پراپ‌های `*.types.ts`.

روی همین ریپو، خروجی امروز:

```
37 پوشه · 218 کامپوننت · 193 محور واریانت · 866 پراپ (513 قابل ویرایش)
```

### چرا `ts-morph` و نه regex

`cva` را می‌شود با regex هم خواند، تا روزی که یکی `compoundVariants` را
چندخطی بنویسد یا یک واریانت را از فایل دیگری ایمپورت کند. مهم‌تر:
`color?: ButtonColor` بدون تایپ‌چکر فقط یک رشته است. با تایپ‌چکر
`'primary' | 'neutral' | 'error' | 'success' | 'basic'` است.

این را در عمل دیدیم: اولین اجرای اسکریپت برای دکمه `control: "none"` داد،
چون `ButtonColor` یک alias بود. وصله‌اش `classifyResolved` است که وقتی
متن تایپ چیزی نمی‌گوید، سراغ چکر می‌رود.

### چرا کپی، و نه فقط پکیج

مدل shadcn یک چیز را درست فهمیده: **کد کامپوننت UI سرمایه‌ی محصول است،
نه وابستگی آن.** وقتی تیمی نیاز دارد دکمه‌اش یک `analyticsId` بگیرد،
راه درست باز کردن issue روی دیزاین سیستم نیست.

اما پکیج هم باید بماند — برای تیمی که می‌خواهد آپدیت بگیرد و کاری به
درون کامپوننت ندارد. این دو با هم تناقض ندارند چون هر دو از یک سورس
ساخته می‌شوند.

### بازنویسی مسیر ایمپورت

مهم‌ترین جزئیات CLI. داخل کتابخانه:

```ts
import { cn } from '../../lib/cn';
import { Icon } from '../icon';
import { LinkButton } from '../button/link-button';
import { alertVariants } from './alert.styles';
```

بعد از `npx nili add alert`، داخل ریپوی مصرف‌کننده:

```ts
import { cn } from '@/lib/cn';
import { Icon } from '@/components/ui/icon';
import { LinkButton } from '@/components/ui/button/link-button';
import { alertVariants } from './alert.styles';   // هم‌پوشه — دست‌نخورده
```

نام مستعارها از `components.json` خوانده می‌شوند، پس هر ساختار پوشه‌ای
کار می‌کند.

### دستورها

```
npx nili init      components.json + توکن‌ها + lib/hooks مشترک
npx nili add …     کامپوننت و هر چه لازم دارد
npx nili list      چه هست، چه نصب است
npx nili diff      کدام فایل از رجیستری فاصله گرفته
```

`add alert` به‌طور خودکار `button`، `icon` و `typography` را هم می‌آورد،
چون گراف وابستگی از خود کد خوانده شده.

### حفاظت در CI

```json
"scripts": {
  "registry": "node scripts/build-registry.mjs",
  "registry:check": "node scripts/build-registry.mjs --check",
  "prebuild": "npm run registry"
}
```

`registry:check` در CI اجرا می‌شود و اگر کسی واریانتی اضافه کرد و رجیستری
را نساخت، بیلد می‌افتد. رجیستری نمی‌تواند از کد عقب بماند.

## ۲. لایه‌ی رفتار برای اورلی‌ها

### مسئله

پنج کامپوننت به موقعیت‌یابی یا مدیریت فوکوس نیاز دارند: `tooltip`,
`dropdown`, `modal`, `drawer`, `date-picker`. وضعیت امروز:

| کامپوننت | موقعیت‌یابی | پورتال | فوکوس |
|---|---|---|---|
| Tooltip | کلاس‌های CSS (`bottom-full mb-2`) | ندارد | — |
| Dropdown | یک `getBoundingClientRect` هنگام باز شدن | ندارد | دستی |
| Modal | — | دارد | `useDismissable` |
| Drawer | — | دارد | `useDismissable` |
| DatePicker | مثل Dropdown | ندارد | دستی |

کامنت خودِ `use-dismissable.ts` این را پیش‌بینی کرده بود:

> اگر سیستم Modal و Popover و Combobox پیدا کند، بردن این‌ها روی Radix یا
> Base UI کار درست است.

### آنچه واقعاً می‌شکند

اینها حالت‌های نادر نیستند؛ در هر داشبوردی روزمره‌اند:

- تولتیپ داخل `overflow: hidden` (سلول جدول، کارت) نصف می‌شود
- دراپ‌داون یک بار اندازه می‌گیرد؛ اسکرول دوم جایش را خراب می‌کند
- هر جد با `transform` ریشه‌ی موقعیت‌یابی مطلق را عوض می‌کند
- تریگر از دید خارج می‌شود، اورلی سر جایش می‌ماند
- فوکوس‌تراپ دستی `contenteditable` را نمی‌بیند و `position: fixed` را
  با `offsetParent` اشتباهی «مخفی» تشخیص می‌دهد

### تصمیم: Floating UI، نه Radix

**Radix نه**، چون API کامپوننت‌ها را می‌شکند. تولتیپ نیلی یک رپر است:

```tsx
<Tooltip content="حذف">{trigger}</Tooltip>
```

Radix شکل مرکب می‌خواهد (`Tooltip.Root` / `Trigger` / `Content`). یعنی
بازنویسی هر ۵ کامپوننت، هر استوری، و هر جای مصرف. برای چیزی که کاربر
اصلاً نمی‌بیند، بهای درستی نیست.

**Floating UI بله**، چون فقط هوک است. زیرِ API موجود می‌نشیند بدون اینکه
یک پراپ عوض شود — همان چیزی که این مهاجرت را برای مصرف‌کننده نامرئی
می‌کند.

Radix هنوز جواب درستی است، اما بعداً: اگر نیلی روزی `Combobox` یا
`Menubar` بگیرد، آنجا سختی کار *رفتار* است نه حساب‌وکتاب مختصات.

### سه فایل

```
src/lib/floating.ts        ترجمه‌ی منطقی↔فیزیکی + استک middleware
src/hooks/use-anchored.ts  برای tooltip, dropdown, popover, date-picker
src/hooks/use-dismissable.ts  همان امضا، درون جدید — modal, drawer
```

### نکته‌ی RTL

این ظریف‌ترین بخش است. Floating UI پسوند تراز (`-start` / `-end`) را
خودش از `direction` عنصر مرجع حل می‌کند. اما *ضلع* را نه — `left` در هر
زبانی چپ است.

پس نیلی که `side="start"` دارد (چپ در انگلیسی، راست در فارسی) باید ضلع
را دستی نگاشت کند و تراز را دست نزند. این کار در `toPlacement()` انجام
می‌شود و جهت را از `useDirection()` می‌خواند، نه از DOM.

### هزینه

```
+ @floating-ui/react   ~11 KB gzip
```

یک وابستگی. `class-variance-authority`، `clsx` و `tailwind-merge` هم
همین‌جا هستند، پس «بدون وابستگی زمان اجرا» دیگر ادعای این کتابخانه نیست
و نباید باشد.

### آنچه عوض نمی‌شود

هیچ پراپی. `side`, `align`, `delay`, `arrow`, `darkMode`, `dismissible` —
همه سر جایشان. `useDismissable` همان امضا را دارد، پس `modal.tsx` و
`drawer.tsx` یک خط هم تغییر نمی‌کنند؛ فقط تراپ فوکوسشان درست می‌شود و
اسکرول‌لاک روی iOS واقعاً کار می‌کند.

## ترتیب اجرا

۱. `npm i @floating-ui/react`
۲. سه فایل رفتار را اضافه کن. مودال و درایر بدون تغییر درست می‌شوند.
۳. تولتیپ را مهاجرت بده (نمونه‌اش هست). استوری‌ها باید بدون تغییر پاس شوند
   — اگر نشدند، چیزی از قلم افتاده.
۴. دراپ‌داون و دیت‌پیکر با همان الگو.
۵. `scripts/build-registry.mjs` و `registry:check` را در CI بگذار.
۶. `packages/cli` را منتشر کن.

مرحله‌ی ۳ آزمون واقعی است: اگر یک استوری هم لازم شد عوض شود، یعنی
مهاجرت شکستنی بوده و باید قبل از بقیه حلش کنی.
